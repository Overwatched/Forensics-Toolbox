Playbook: Bildfil — härkomst

Statisk checklista för IT-forensikern. Stegen leder bedömningen — de ger inte automatisk slutsats.

Använd som hypotesstöd. Dokumentera vad du hittade, vad som saknas, och vilka begränsningar som gäller (OS-version, OEM, ofullständigt extrakt). Öppna verktygen i sidopanelen (Time Converter, Photos.sqlite Queries, Android Queries, ExifTool-länk).
Stegöversikt
  1. Media-DB: vilken app / vilka tider?
  2. Var kameran aktiv?
  3. Var applikationen aktiv?
  4. Vad säger filens metadata (EXIF)?
  5. Andra faktorer
1

Analysera media-databasen (app + tider)

Mål: koppla filnamn/UUID/path till skapande-/importtid och eventuell källapp (bundle-ID / owner package).

iOS

  • Öppna Media/PhotoData/Photos.sqlite
  • Kör schema-probe, sedan sök via filnamn/UUID
  • Notera ZCREATORBUNDLEID / ZEDITORBUNDLEID, created/modified/added (Cocoa → Time Converter)

Android

  • Öppna MediaStore external.db (files/images)
  • Sök path/filnamn; notera date_added, date_taken, owner_package_name

Verktyg: Photos.sqlite Queries · Android Queries (MediaStore) · Time Converter · DB Browser

Begränsningar

  • Schema/FK skiljer sig mellan OS-versioner
  • Saknad creator betyder inte “ingen app” — bara saknad metadata
2

Var kameran aktiv på enheten?

Mål: bedöma om tidpunkten för bilden sammanfaller med kamerarelaterad aktivitet (DCIM/Camera, kamera-app, OEM gallery/camera-DB).

iOS

  • Jämför Photos.sqlite-tider med KnowledgeC / andra sensor-/appartefakter (via iLEAPP)
  • Bundle com.apple.camera som creator är en stark indikator — men inte enda vägen

Android

  • SQL: filer under DCIM/Camera runt tid T
  • SQL: owner_package_name liknande camera
  • Kör ALEAPP för OEM camera/gallery (Samsung CMH m.fl.)

Verktyg: Android Queries (Kamera) · iLEAPP · ALEAPP · Time Converter

Begränsningar

  • Andra appar kan spara under DCIM
  • Importerade bilder kan ha kameralik EXIF utan lokal kamerasession
3

Var applikationen aktiv?

Mål: korsreferera om den misstänkta källappen (WhatsApp, Safari, Files, Gallery, …) var i förgrunden / använd nära tidpunkten.

iOS

  • KnowledgeC / Biome / relaterade artifacts via iLEAPP
  • Jämför app bundle-ID från steg 1 med usage-artefakter

Android

  • UsageStats under /data/system/usagestats/ (ofta XML) → ALEAPP
  • Android Queries har tips/mallar när SQLite finns

Verktyg: Android Queries (App-användning) · iLEAPP · ALEAPP

Begränsningar

  • UsageStats kan saknas, vara roterad eller OEM-modifierad
  • Bakgrundsaktivitet ≠ användarinteraktion
4

Vad säger filens metadata (EXIF m.m.)?

Mål: jämföra embedded metadata med databastider och källhypotes.

  • DateTimeOriginal / CreateDate / ModifyDate
  • Make / Model / Software / HostComputer
  • GPS (om finns) — policy/integritet!
  • Saknad EXIF kan tyda på export/omkodning/messaging-app

Verktyg: ExifTool (extern länk under Verktyg & releaser)

Begränsningar

  • EXIF kan redigeras eller strippas
  • DB-tid och EXIF-tid behöver inte vara samma händelse
5

Andra faktorer

Komplettera med kontext som ofta avgör bedömningen:

  • Messaging (WhatsApp, Signal, SMS/MMS) — mottagen bilaga vs tagen bild
  • Moln/sync (iCloud Photos, Google Photos, OneDrive)
  • AirDrop / Nearby Share / Bluetooth-överföring
  • Screenshot-heuristik (filnamn, resolution, saknad kamera-EXIF)
  • Hashjämförelse mot andra enheter/medier
  • Trash/hidden/favorit-flaggor i Photos/MediaStore
  • Sideload / USB-MTP / SD-kortskopior

Verktyg: iLEAPP · ALEAPP · Hash Calculator · CyberChef · OSINT-länkar vid behov

Sammanfatta bedömningen

  • Vad stöder hypotesen “tagen med enhetens kamera”?
  • Vad stöder “importerad / mottagen / synkad”?
  • Vad är okänt p.g.a. saknade artefakter?
